# Benchmark Results: Baseline vs. Dashboard Kit

**Configuration:**
- **Model:** Claude Sonnet 5.5 (Effort: High)
- **Client:** Claude Desktop
- **Tokenizer:** tiktokenizer.vercel.app (gpt-4o)
- **Metric:** Output tokens generated by the model

*Note: The "Kit" run measures only the JSON specs the agent outputs. Tool-call overhead and the final HTML rendered by the server are excluded, as the goal is to measure the reduction in generative output.*

## Results

| Prompt | Scenario | Baseline Tokens | Kit Tokens | Reduction |
| :--- | :--- | :--- | :--- | :--- |
| **P1** | Simple Table | 2,533 | 134 | **94.7%** |
| **P2** | Simple Metric | 1,028 | 76 | **92.6%** |
| **P3** | Table + Metric (Side-by-side) | 3,189 | 197 | **93.8%** |
| **P4** | Brand-Constrained | *Pending* | *Pending* | *Pending* |
| **P5** | Complex Multi-element | *Pending* | *Pending* | *Pending* |

**Average Token Reduction (P1-P3): 93.7%**

## Observations
- **Scaling:** In the baseline, adding a component and layout (P3) increased output tokens by ~26% compared to P1. In the Kit run, adding the same complexity only increased output by ~47 tokens, because the rendering logic is handled by the server.
- **Determinism:** The baseline model hallucinated extra features (e.g., accessibility text, assumed USD) and varied its code structure. The Kit run enforced strict Zod schema validation, resulting in identical structure every time.
- **Brand Safety:** The baseline had to manually map hex codes to CSS. The Kit run applied brand tokens deterministically via the server.
